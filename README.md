# Nooni

Storefront for [nooni.dk](https://nooni.dk) — a small Danish family business
making personalised 3D-printed products for everyday family life.

This repository holds the marketing site + storefront. Commerce backend
is Shopify (headless via the Storefront API); the frontend is Next.js
deployed on Vercel.

## Reading order for newcomers

1. **`BRAND.md`** — the locked wordmark spec. Read first.
2. **`VISION.md`** — brand identity, products, design system, and the
   current project status. The strategy doc.
3. **`AGENTS.md`** — branch policy and other rules that any contributor
   (human or AI) must follow.
4. **This file** — local setup and the codebase tour below.

## Local setup

```bash
npm install
cp .env.example .env.local   # then fill in the Shopify token
npm run dev
```

Open <http://localhost:3000>.

### Required env vars

| Key | Purpose |
|---|---|
| `NEXT_PUBLIC_SHOPIFY_STORE_DOMAIN` | e.g. `nooni-2711.myshopify.com` |
| `NEXT_PUBLIC_SHOPIFY_STOREFRONT_TOKEN` | public Storefront API access token |

Both come from Shopify Admin → Apps → the headless storefront → API
credentials. They're prefixed `NEXT_PUBLIC_` because the Storefront API
is designed to be called from the browser; the tokens are public-safe
and rate-limited per token.

In Vercel, set the same two vars for both **Preview** and **Production**
environments.

### Optional env vars

Server-only, never prefixed `NEXT_PUBLIC_`. Only needed to test the
contact form (`/kontakt`) locally; the rest of the site runs without them.

| Key | Purpose |
|---|---|
| `RESEND_API_KEY` | sends contact-form mail via Resend |
| `CONTACT_FROM` | sender address; defaults to Resend's onboarding sender |

## Branch model

- **`main`** — active development. Pushes deploy to a Vercel preview URL.
- **`production`** — what `nooni.dk` actually serves. Protected on
  GitHub: only the repo owner can update it, by merging a pull request
  from `main`.

### Contributing

The repo is public; to push branches you need to be added as a
collaborator (ask Steffan). Then:

1. Branch off the latest `main`.
2. Push the branch and open a pull request into `main`. Vercel comments
   a preview URL on the pull request.
3. Steffan reviews and merges. Merged branches are deleted automatically.
4. Steffan ships `main` to `production` when it's ready.

Keep each pull request to one topic. AI agents working on the repo must
follow `AGENTS.md`, which spells out the same rules.

To ship to production (owner only): open a pull request from `main` into
`production`, then merge it on GitHub.

```bash
gh pr create --base production --head main --title "Ship to production"
```

## Where SEO and content live

| What | Where |
|---|---|
| Site-wide title, description, Open Graph, Search Console verification | `metadata` in `src/app/layout.tsx` |
| Per-page title and description | `metadata` in each `src/app/*/page.tsx` |
| Product page title and description | `generateMetadata` in `src/app/produkter/[handle]/page.tsx`, built from the product's title and description in Shopify |
| Product titles, descriptions, images, prices | Shopify Admin, not this repo |
| Blog posts | Markdown files in `content/posts/`, loaded by `src/lib/blog.ts` |
| `sitemap.xml` | `src/app/sitemap.ts`, a hand-maintained list of URLs |
| `robots.txt` | `src/app/robots.ts` |
| Structured data (JSON-LD) | none yet |

## The design system

- Tailwind v4 with all design tokens defined in `src/app/globals.css`
  under `@theme`. Use `bg-nooni-bg`, `text-nooni-headline`, etc. —
  never raw hex values.
- The Nooni wordmark **must** be rendered via `<Logo />` (see
  `BRAND.md` for the spec). Never inline.
- The boho-arch motif is the signature visual element — see
  `Arch.tsx` and `HeroArches.tsx` for the implementation and the
  load-bearing geometry / scroll-retract behaviour.
- The "liquid glass" surface (`.nooni-glass`, used by the navbar and
  product cards) has stacking-context constraints noted at the top of
  `src/app/layout.tsx`. Read them before adding any `transform`,
  `filter`, or `will-change` to ancestor elements.
